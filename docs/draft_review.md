# Draft & Review vertical slice

Implemented 12 November 2026 following the owner's attached overnight task. This is early project planning, not an official funding application, eligibility assessment or independent expert review. Use fictional information only.

## What is available

Open an existing saved concept and select **04 — Draft & review / Luonnos ja arviointi**. No model request occurs when opening the section, switching languages or rerunning the app.

1. **Generate draft** creates a validated, bounded application draft from the saved original idea and concept. Local Qwen remains the default; optional provider/cloud settings are inside the initially collapsed **Advanced options / Lisäasetukset** section.
2. The document shows summary, need, target groups/beneficiaries, general/specific objectives, work packages/activities, outputs/results, indicators, possible longer-term impact, known/proposed partner roles, preliminary timeline, risks/mitigations, assumptions, sustainability and questions. Unknown information must remain explicit; proposed targets and periods need human confirmation.
3. Python checks show a summary and expandable details for required data, O/A/R/I links, WP membership/timeline references, duplicates and advisory disconnections. Blocking error counts remain visible before approval. Schema validity and connected IDs do not establish useful intervention logic or an appropriate indicator.
4. Choose **Improve the draft / Paranna luonnosta**. The first **Review draft** creates AI suggestions with field/ID references and exact quotations. The summary appears first; full assessment, strengths, findings/evidence, gaps and uncertainties are under **Review details and evidence**. Quotes must occur in their cited field; invented or misplaced evidence prevents saving the review. Deterministic findings stay separate. Direct text editing is not supported; the interface explains this instead of offering an Edit button.
5. Choose **Approve and export / Hyväksy ja vie**. Read the exact draft, findings and uncertainties, check the explicit human confirmation and click **Approve and prepare export / Hyväksy ja valmistele vienti**. The interface explains that approval locks this version. No review, deterministic errors, stale displayed material and mismatching review/checks block approval. Changing the generation provider is not required to approve an existing review.
6. Approved records are locked and the primary **Download approved draft / Lataa hyväksytty luonnos** button becomes available, with the actual Markdown (.md) format stated. Approval and downloading are separate explicit actions. Export reloads the approved record, revalidates its supported draft/review/evidence/checks and escapes generated HTML/Markdown. The disclaimer, original content, references, findings, review and generation metadata are included. The existing concept PDF in stage02 remains separate and unchanged.

The AI never approves, silently edits or automatically accepts a suggestion. There is no inline correction editor or automatic correction-acceptance feature in this slice. You can explicitly regenerate a mutable draft; this replaces it and invalidates its review atomically. A fresh replacement acknowledgment is required for each displayed snapshot. **There is no draft history**; preserve evidence separately before replacing. Approved records require a new project record for changes. Regeneration is not a promise that quality improves.

Regeneration and AI review replacement are inside collapsed Advanced options, each with a warning and source-bound replacement acknowledgment before its button enables. Generation settings/cloud consent remain there too. Opening the section does not call a model. The first draft and first review remain plain main actions. After approval the generation/replacement controls disappear and the download stays prominent.

The two finalization choices use canonical per-project session values, so language changes and the four workflow stages retain the choice. Approval confirmation survives ordinary reruns/stage navigation on the same source. Switching from approval back to improvement removes that confirmation control; returning requires a fresh confirmation. A new draft/review/source likewise cannot reuse an old confirmation. This is not saved document versioning.

The AI summary is a display excerpt of at most360 characters plus deterministic counts of suggestions/gaps/uncertainties, not a quality score or an independent human assessment. Full original assessment and exact evidence remain available in the collapsed details and unchanged in storage. Nothing is applied automatically; the user decides whether an observation is useful.

## Providers and language

English and Finnish labels are supported. Generation requests the chosen language but cannot guarantee fluent text; saved text is never translated by toggling the interface. Model-produced and official source text remains in its original language. Stable JSON keys/IDs are never translated. The document headings and export labels follow the selected language.

Active instructions as of13November are `draft_workflow_v2` / `review_workflow_v3` in `draft_workflow.py`, with concept_v2 professional-planning guidance; see [current quality/readiness](mistral_readiness.md). Historical benchmark recipes/results remain unchanged. The local stage adapter uses the verified native LM Studio reasoning-control route `/api/v1/chat`: `reasoning=off`, `store=false`, no integrations/tools, temperature0.2, output limits4096 draft/2048 review and180-second HTTP phase timeout. Schema is supplied in the system prompt and strictly validated locally. It checks returned reasoning and token-cap/incomplete signals and does not silently switch endpoints/providers or retry. This does not change the older concept-generation client.

Default local model is `LM_STUDIO_MODEL` or `qwen3.5-4b`; optional `HANKELUOTSI_DRAFT_MODEL` and `HANKELUOTSI_REVIEW_MODEL` override only their corresponding stage. The local URL comes from `LM_STUDIO_BASE_URL`, must be a credential-free loopback `/v1` endpoint, and defaults to `http://127.0.0.1:1234/v1`. No models are downloaded or configuration changed automatically.

The native API may omit finish reason. A complete Pydantic-valid document with no observed truncation can be saved as a **draft**, with unknown/incomplete completion metadata retained and a visible warning. This is never relabelled as `stop`, a benchmark first-attempt success or expert approval. Malformed output, active reasoning, an observed token cap, timeout or explicit abnormal finish preserves the previous valid persisted state.

Mistral uses the existing adapter with explicit4096 draft/2048 review output-token budgets and180-second phase timeouts. Consent is tied to the displayed source fingerprint and reset after an attempted stage or a source/provider change; it cannot authorize sending a newer unseen record. The next call sends original idea/concept for draft generation, or original idea/draft/checks for review, with schema and instructions. No saved project is sent on selection/rerun alone. There is no automatic fallback. The exact cloud model remains environment-configured; no model is guessed.

No paid Mistral call was made during development. Follow [Mistral diagnosis](mistral_diagnosis.md) and [secure setup](mistral_setup.md) for the owner's subsequent real-key model/balance/pricing checks. ## Persistence, versions and concurrency

The additive `ApplicationDraft` and `ReviewReport` each have schema_version 1; original `ProjectIdea`/`ConceptPaper` remain unchanged. Draft-specific version parsing rejects unsupported or fractional/boolean versions. Existing database columns/state machine are reused with **no table migration**. Generic old stage payloads can still be loaded by the repository, but the new UI/service refuses unsupported draft/review contracts rather than silently replacing them. Database record-version reading also rejects a fractional stored version instead of coercing it to 1.

Optional generation_metadata is always overwritten by service-trusted provider/model/prompt/finish metadata after validation, never accepted as authority from a model. It is persisted with each new draft/review. Known partner names marked `provided` must occur exactly in the original idea; a supplied name alone does not prove a proposed responsibility or commitment. Other unsupported semantic claims still require human review.

`created → concept_ready → draft_ready → reviewed → approved` remains the durable workflow. One atomic repository snapshot supplies both input and source fingerprint; a compare-and-swap inside the save/approval transaction rejects changes made while the model ran. The previous valid output remains intact on failure. In-memory state only stores transient controls/notices/operation IDs, not the authoritative draft.

A per-project nonblocking thread/kernel file lock prevents concurrent expensive stages even across processes using the same database path; it releases on process exit. Lock files contain no project text and live under the OS temporary directory. Completed operation IDs are checked durably before another provider call; failed operations can be explicitly retried. The database is never held in a long model-call write transaction. Direct repository edits outside the workflow are still protected at save time by CAS.

## Follow-up: source-selected review citations — 13 November 2026

The owner authorized continued work on the observed quotation failure. **`review_workflow_v2`** now asks the model to choose an `evidence_id` from a deterministic source catalogue, rather than invent/retype a quotation and reference. Internal `ReviewSelection` contains the usual assessment fields and findings with evidence_id/observation/suggestion/severity. The application resolves the exact source quote and section/ID, constructs the unchanged persisted `ReviewReport` v1, and runs the original strict quotation validator again. Unknown selectors, stale catalogues, tampered quotes and the old model-written-quote transport are rejected; there is no fuzzy matching, quote repair or weakening of validation.

The catalogue excludes IDs/metadata as quoted text, prioritizes breadth across draft sections/entities, and is bounded to 48 excerpts, 6000 quoted characters and 240 characters per excerpt. Those are excerpt limits, not a hard token limit for the whole request. Its source hash ties it to the exact draft. The model receives the original idea, bounded catalogue, structural relationships, partner status/timeline context and unchanged deterministic findings instead of a duplicate full draft. If excerpts are clipped/omitted, the saved review explicitly warns about partial coverage. Observations and suggestions are still unverified AI judgments; exact citation provenance cannot prove their truth or completeness.

Every new review includes an application-authored uncertainty explaining that quotes were copied from source and observations remain suggestions. A maximum of five model uncertainties leaves room for that notice within the existing persisted schema. Original reviews/drafts, their versions and approved records are not migrated or rewritten. Generation provenance records review_workflow_v2. Draft prompting/budget remain unchanged; review output budget is now **2048**, with the same 180-second phase timeout and zero automatic retries, for both optional providers. No Mistral call was made.
